# Audit + fix report — 2026-08-13

Product-owner ask: audit the current state, fix the substantial bugs, and research how to grow
detection/removal coverage (credit bureaus, HR/applicant-screening, third-party data) while
maximising user anonymity and protection. Method: four parallel deep audits (state machine/clocks,
security/identity, playbooks/templates/ladder, API/worker/data layer) cross-checked by hand, three
parallel research sweeps (HR-screening ecosystem, bureau/regulatory landscape, detection +
prevention + category effectiveness), then same-day fixes. Research synthesis:
`docs/13-research-2026-08.md`. This file is the audit narrative and the fix ledger.

## 1. Baseline (before fixes — all of it held)

Build green across 7 packages; 489 tests green; spec-audit 0 failures (62 checks); negative
fixtures 31/31 rejected; version seal intact; axe gate green (light/dark/Leichte Sprache); API
boots and serves the census end to end. The legally load-bearing invariants were verified sound in
depth by two independent passes: `deadlineAt` has exactly one writer backed by a DB CHECK; email
structurally cannot claim provability; ESCALATED has one human-only inbound edge (graph-asserted +
DB trigger); the anti-stalker subject binding is a branded type with no API surface that can name a
person; idempotency carries the cycle dimension with the load-bearing self-exclusion; the counsel
gate (every playbook `active:false`) held at every layer.

## 2. What the audit found and this pass FIXED (all verified by tests; suite now 525)

### Critical
- **F1 — the wire guard killed the chase path.** Send-level idempotency counted OUTBOUND_COPY
  evidence per request LIFETIME, so the user-authorised registered re-send was refused forever
  (`FAILED → NEEDS_HUMAN → resend → FAILED …`) and the Art. 12(3) clock was unreachable after any
  email send — the product's central legal mechanism, dead on the real dispatch path. Found
  independently by two audit passes. Fix: the guard is per dispatch ATTEMPT, scoped by the most
  recent entry into READY (`prisma-worker.repo.ts`), which is exactly what spec §5b says.
  Regression: the full chase now runs to a statutory clock in `dispatch-flow.test.ts`.

### High
- **W1 — no compare-and-swap on any state transition.** Sweep + queued job (or two ops reviewers,
  or a double-click) could both act on one snapshot: two identical letters on the wire, forked
  evidence chain, duplicate events in the append-only log. Fix: every transition write is now
  `updateMany({id, state: from})` inside the transaction; losers get `StaleTransitionError`
  (core) mapped to 409 `STALE_STATE`; the worker sweep also has a re-entrancy latch.
- **W3 — correlated replies were never ingested.** `assignInboundDocument` only updated the row;
  nothing produced `ingest-response` jobs, so a correlated reply left the request in
  AWAITING_RESPONSE and the statutory timer would draft an Art. 77 complaint **alleging silence
  with the reply on file**. Fix: assignment now enqueues the ingest job (same engine as the
  deadline timers; OpsModule imports the RequestsModule scheduler); the sandbox-refused document
  fails closed to NEEDS_HUMAN with the ControllerResponse — and therefore proven receipt — recorded.
- **W4 — the BYO-Datenkopie upload was unauthenticated in the real-auth posture.** The browser
  posted straight to the API with no bearer (the session is an httpOnly cookie), so the flagship
  same-day-utility feature 403'd everywhere except the fixture alpha. Fix: same-origin proxy route
  (`app/akte/upload/route.ts`) attaches the bearer server-side; the form now renders the API's
  message instead of a generic "failed".
- **W5 — Art. 12(3) as `30 × 86 400 000 ms`.** Fired up to a full day early on 31-day months — an
  escalation draft asserting the month ran out while the controller legally had time left. Fix:
  `statutoryDeadlineAt()` (new `packages/core/src/state-machine/statutory-clock.ts`): calendar
  month per Reg. 1182/71 / EDPB Guidelines 01/2022 §54, Europe/Berlin end of day, clamped to month
  end, extended over Sat/Sun + bundesweite Feiertage (computus included). Land-specific holidays
  are TODO(counsel). `deadlineDays` now parameterises only the provisional hint.
- **F2 — `NO_RESPONSE` was unreachable.** Every terminal path out of a provable-silence case
  produced `ABANDONED` (excluded from stats), so total silence on a provable month — the fact the
  two-clock machinery exists to evidence — could never be recorded against a controller. Fix:
  silence provenance wins over discard mechanics (`outcomeFor` in machine.ts + spec §Outcome
  updated); a silence-born discard/failed escalation closes as `NO_RESPONSE` and counts.
- **P1 — the confidence floor collapsed on malformed playbook JSON.** DB documents are cast, not
  validated; `confidence < undefined` is `false`, so a document missing
  `humanReviewIfConfidenceBelow` let hostile parser output auto-decide outcomes (the exact docs/06
  C4 attack). Fix: fail-closed floors in `validateResponse`, `apply()` and the ingest snapshot;
  spec-audit gains a gate that validates the SEED's fixture documents through the full schema+lint
  stack (which caught the fixtures being invalid: `demo:true`, missing `provenance`/`seatDpa`).
- **P2/P3/P4 — the flagship chain's last link.** The bureau-erasure demo fixture carried the
  UNBOUNDED erasure template docs/07 forbids (fixed: bounded template + `scopeSource`, version
  bump to v3); nothing bound a PROVENANCE_CHAIN request to a *scoped* playbook (fixed: both-ways
  check at insert); and nothing ever constructed the `PartialErasureScope` at dispatch, so the
  chain's final send always dead-ended in the human queue even after counsel activation (fixed:
  `loadDispatchable` derives the scope from the same bureau's own provenance ledger via
  `deriveErasureScope`, fail-closed).
- **P6 — a rejection letter validated as COMPLIED.** "Ihre Daten wurden **nicht** gelöscht"
  contains the `compliedIf` needle "gelöscht" and matched nothing in `refusedIf`. Fix: negation
  needles added to eight sealed playbooks (six enrichment brokers + both stencils), versions
  bumped 1→2, corpus re-sealed; negated replies now trip the contradiction path → NEEDS_HUMAN.
  New truth-table suite `validate-response.test.ts`.
- **H1 — the KEK resolver was a deny-list.** `DevKekResolver` refused only literal `production`;
  any staging/unset/misspelled NODE_ENV silently sealed real secrets under a source-derivable key,
  and the real resolver was opt-in via an env var `.env.example` never mentioned. Fix: allow-list
  (dev/test only), `SCRAPER_KEK_MODE`/`SCRAPER_KEK_USER` documented, and the API gained the boot
  gate it never had (`assertApiStartupSafe`: KEK mode + CORS origins required outside dev/test).
- **F3b — the one real postal adapter faked delivery.** LetterXpress stamped `origin: 'CARRIER'` +
  `deliveredAt: now()` onto a LODGEMENT response — satisfying every provable-send check and one
  env change away from starting statutory clocks on invented delivery times. Fix: the adapter
  returns `proof: null` unconditionally until the Auslieferungsbeleg fetch exists (OQ-11); sends
  degrade honestly to the provisional clock.
- **H3 — the hostile-PDF parser ran inside the API process.** CLAUDE.md §2's "isolated service"
  was a library import: pdf.js executed in the process holding the PrismaClient. Fix:
  `createIsolatedDatenkopieSandbox()` runs every parse in a fresh child process with a scrubbed
  env (allow-list: NODE_ENV, PATH — no DATABASE_URL, no keys), size/time budgets, and the safety
  envelope re-applied parent-side across the JSON boundary. The upload path uses it; tests prove
  the fixture parses and the injection fixture still floors to confidence 0 across the boundary.

### Medium
- **M1/W10 — retention purge existed only as schema.** `purgeRawAt` was written everywhere and
  executed by nothing (0005 even built the index). Fix: the worker's sweep now runs
  `sweepDueRawPurges` — blob delete first, then tombstone — for ControllerResponse and
  InboundDocument; the object-store delete is a logged no-op until the S3-EU adapter lands
  (TODO(safety) kept loud).
- **M2 — the worker's production guard validated selectors nothing consumed.** Setting the five
  `SCRAPER_*` provider vars passed the boot check while `main.ts` hardwired stubs. Fix: the guard
  now refuses ANY non-dev boot outright until a provider factory dereferences those names — and its
  dev allow-list was also fixed (it previously checked only `!== 'production'`, the H1 trap again).
- **M3 — anomaly review was a log line.** SUBJECT_MISMATCH (someone uploading a different person's
  Datenkopie — the highest-signal abuse event this product can observe) went to stdout. Fix:
  migration 0013 adds `AnomalyEvent` (deliberately FK-free so abuse audit survives account
  erasure); the match gate and the upload rate-cap write rows; `GET /ops/anomalies` lists them
  behind the ops role.
- **M5/W12 — the register enumeration oracle + conflict 500s.** `POST /auth/register` answered
  EMAIL_TAKEN (DPIA R2 said "no enumeration oracle on any auth path"); concurrent duplicates
  500'd. Fix: taken addresses get a DECOY registration — same shape, same KDF cost, cuid-shaped
  id, nothing persisted; concurrent P2002s (register, request idempotency, inbound assignment)
  now map to the same conflicts their sequential paths produce.
- **W6 — the humanQueued event flood.** Every 15s sweep appended an immortal RequestEvent per
  undispatchable READY row (~5 760/day/request into an append-only table). Fix: deduped against
  the latest event; a CHANGED reason is still a new fact.
- **W9 — TRUNCATE bypassed the append-only ledgers.** Row-level triggers don't fire on TRUNCATE.
  Fix: 0013 adds statement-level BEFORE TRUNCATE triggers; tests that reset the throwaway DB now
  disable them explicitly (the visible act is the point); regression test included.
- **W11 — `maxSendsPerControllerPerHour` was decorative.** Config-validated, consumed by nothing.
  Fix: the gateway counts OUTBOUND_COPY per controller per hour and refuses over-cap sends into
  the human queue (an automatic retry of a flood IS the flood).
- **W13 — ART77_SENT evidence could outlive a failed send.** The chained record was written
  outside the transition transaction. Fix: chain-head read + evidence + CAS + event now commit
  atomically.
- **W15 — hostile dates 500'd the upload; decomposed umlauts false-rejected the owner.**
  "45.13.2024" produced an Invalid Date that crashed the match gate; NFD "Müller" folded to
  "muller" ≠ "mueller". Fix: calendar-validated date parsing, NaN guard (clean "unreadable"),
  NFC-first normalisation. Tests for all three.
- **F5 — the Art. 12(5) cooling mechanism was specified and unwired.** `mayOpenNewCycle` had zero
  call sites. Fix: wired into `createRequest` (30-day conservative default; the NUMBER stays
  OQ-9/counsel's): a rapid repeat returns `RE_EXERCISE_CONFIRMATION_REQUIRED` → the DTO's new
  `reExercise: true` is the explicit user confirmation; distinct causes (provenance chain) pass
  untouched, as does post-window annual re-access.
- **W7 (largest slices) — dead ends.** Ops queue rows for undispatchable READY requests rendered
  five resolution buttons that always 409'd (now: an honest "waiting on the system" line, and the
  clock tag only renders when a clock actually runs); `startRequest` swallowed the API's answer
  (now surfaced under the button). W8: the two unvalidated body paths that could 500 on
  non-string input now coerce (the auth controllers' pattern).

### Hygiene with teeth

- German injection markers added to the doc-sandbox (the hostile documents are German; the list
  was English-only).
- CORS origins are env-driven with the file:// "null" origin stripped outside dev.
- `acxiom`/`capaneo` census defaults corrected to Art. 21(2) (least-collecting instrument first).
- Templates are now inside the outcome-promise sweep (spec-audit `TPL-PROMISE`); the phantom

  boundary; the dead `enterReady()` footgun is deleted; a provable-send upgrade nulls the spent
  provisional hint; the dev scheduler keys timers like the worker does; invariant renumbering
  (3a/3b → 4a/4b) reconciled across CLAUDE.md, the spec, and code comments.
- `pnpm readiness` exists (scripts/readiness.mjs): the pre-send checklist's promised mechanical

- docs/11 (DPIA) corrected to describe implemented reality (H2/M5) so counsel never reviews an

## 3. Flagged, NOT fixed (each needs a design/counsel decision first)

> **Status as of 2026-08-14:** those decisions were taken and seven of the eight items below are now
> implemented — see `AUDIT-2026-08-14-DECISIONS.md` for the fix ledger. The exception is **item 2
> (H2/M4) together with item 3 (W14)**: identity PII and credit-file contents are still plaintext at
> rest and there is still no account-erasure path. Everything the list says about them still holds.

1. **F3a — no path from a lodged registered send to a statutory clock (the async-proof gap).**
   With the F3b honesty fix, a real registered send degrades to provisional until the
   Auslieferungsbeleg arrives — and the graph has no upgrade edge, so in production the statutory
   clock is reachable only via the chase's registered re-send whose proof returns synchronously
   (which no honest adapter does). This is THE remaining structural gap on the legal path.
   Proposal (spec-first, three places, counsel-reviewed): a dedicated `AWAITING_DELIVERY_PROOF`
   state between SENT and AWAITING_RESPONSE — entered on registered lodgement, exited by
   `provableSendConfirmed` when the retrieval job (OQ-11) fetches the receipt, with `deadlineAt`
   computed from the EVIDENCED delivery time. A dedicated state preserves the C1 graph property
   (AWAITING_RESPONSE_PROVISIONAL still cannot reach escalation) instead of weakening it to a
   guard. Blocked on: OQ-11 (vendor), a timeout policy for proof-never-arrives, and the tri-doc
   normative edit.
2. **H2 — identity PII and credit-file contents are plaintext at rest**, and no crypto-shred path
   exists. The envelope machinery is proven (TOTP); extending it to `Identity`/`IdentityAddress`/
   `CreditFileEntry` is a schema+repository migration that should ride with the KMS decision and
   the R6 backup answer. Launch-gated in the checklist; DPIA now says so honestly. Same cluster:
   **M4** credit-store segregation (separate role/credentials — checklist D6).
3. **W14 — account erasure vs the append-only ledgers.** Cascades declared in the schema can never
   fire through the 0001 triggers, so the promised self-service Art. 17 path cannot be implemented
   without an explicit design: anonymise-in-place (scrub PII, keep the ledger) vs an audited
   SECURITY-DEFINER purge. Counsel question as much as engineering.
4. **P5 — `seatDpa` is schema-required only for provenance playbooks**, nothing consumes it at
   escalation time, and "venue = user's Land DPA" (US brokers, OQ-20) is inexpressible. Proposal:
   schema conditional (any DRAFT_ART77 ⇒ `seatDpa` or `venue: USER_RESIDENCE`), surface it in the
   ops escalation payload. Touches sealed playbooks → version bumps; do it as its own pass.
5. **L2 — session token not rotated at MFA/step-up completion** (a pre-MFA token becomes fully
   privileged in place). Cheap fix, but it threads through the web-next cookie flow; do
   deliberately, not as a drive-by.
6. **L5 — the legacy single-file alpha (`apps/web/index.html`)** renders API JSON via innerHTML.
   It is the published demo artifact, not the product UI (web-next is React/escaped). Either
   retire it or convert its render paths to textContent before it ever faces non-census data.
7. Cosmetics deliberately left: comment-narrative drift inside APPLIED migrations 0008/0009
   (editing applied migration files changes their checksums); the 33 stale doc-refs in planning
   docs (spec-audit warnings — prune in a docs pass); L1 scrypt "OWASP" label (params are a
   defensible interactive trade-off; relabel or raise N with a perf check).
8. **Ops anomaly screen** — the API and table exist (M3); the ops UI lists only the queue+inbox.
   Add the anomalies panel in the next ops-UI pass. Likewise the remaining swallowed
   `ApiResult`s in ops server actions (resolve/file/discard/assign render no failure detail yet).
